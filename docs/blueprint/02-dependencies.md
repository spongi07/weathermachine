# Dependencies — why, where, alternative

Policy: a dependency must remove real risk or real code. Versions are pinned
in `Cargo.toml`, `Cargo.lock` and `ui/Cargo.lock`, and CI builds with
`--locked`. `cargo audit` runs in CI as an advisory job.

## Runtime (server workspace)

| Crate | Why | Where | Alternative considered |
|---|---|---|---|
| `tokio` | Async runtime: timers, TCP, signals, sync primitives (mpsc/watch/semaphore) | all I/O crates | `async-std` (unmaintained), `smol` (smaller ecosystem) |
| `reqwest` (rustls) | HTTP client: timeouts, gzip, conditional requests, connection pooling | `wm-net::HttpFetcher` only | `hyper` directly (more code), `ureq` (blocking) |
| `rustls` (aws-lc-rs provider) | TLS without OpenSSL; FIPS-capable provider; static linking into distroless | process-wide provider in `wm-app::telemetry` | `native-tls`/OpenSSL (system dependency in the image), `ring` provider (fine; aws-lc-rs is the rustls default) |
| `tokio-tungstenite` | Polymarket market WebSocket | `wm-polymarket::ws` | `fastwebsockets` (lower level) |
| `serde`, `serde_json` | Typed JSON for providers, events, journal, API | everywhere | `simd-json` (unnecessary at these volumes) |
| `toml` | Configuration files | `wm-app::config` | YAML (ambiguous), JSON (no comments) |
| `chrono` | Timestamps, durations | everywhere | `time` (equally good; chrono pairs with chrono-tz) |
| `chrono-tz` | IANA time zones compiled in (DST-correct local days; no tzdata in the image) | `wm-core::time`, strategies, config | `jiff` (newer; would also work), system tzdata (absent in distroless) |
| `sqlx` (Postgres, rustls, migrate) | Async PostgreSQL, pooling, embedded migrations, typed binds | `wm-storage` | `tokio-postgres` (manual migrations), `diesel` (sync core, heavier DSL) |
| `sha2`, `hex` | Content hashes: raw payloads, rules text, observation fingerprints | `wm-core::hash` | `blake3` (faster, but SHA-256 is the audit standard) |
| `uuid` (v7) | Time-ordered run ids | `wm-core::ids::RunId` | ULID crate |
| `thiserror` | Typed error enums in libraries | all library crates | hand-written `impl Error` |
| `anyhow` | Error context at the binary edge only | `wm-app` | `eyre` |
| `tracing`, `tracing-subscriber` (JSON) | Structured logs with spans; JSON in containers | everywhere / `wm-app` | `log` + `env_logger` (no structure) |
| `metrics`, `metrics-exporter-prometheus` | Counters/gauges/histograms; `/metrics` rendered by our own server (no extra listener) | `wm-net`, `wm-weather`, `wm-app` | `prometheus` crate (global registry, more boilerplate) |
| `axum` | HTTP API, SSE, static files, middleware | `wm-app::http` | `actix-web` (own runtime), `warp` (less maintained) |
| `tower-http` | Compression, static files, timeouts, security headers, tracing | `wm-app::http` | hand-written middleware |
| `futures-util` | Stream combinators (SSE, WebSocket) | `wm-app`, `wm-polymarket` | `tokio-stream` |
| `bytes` | Zero-copy bodies (raw payloads, serialized snapshots shared by all SSE clients) | `wm-net`, `wm-polymarket`, `wm-app` | `Vec<u8>` copies |
| `clap` (derive, env) | CLI with env-var fallbacks | `wm-app::cli` | `argh` (fewer features) |
| `csv` | IEM historical imports | `wm-backtest::historical` | manual splitting (quoting bugs) |

## Dashboard (`ui/`, wasm32)

| Crate | Why | Alternative |
|---|---|---|
| `leptos` (csr) | Fine-grained reactive UI in Rust; memoised panels re-render only on change | `yew` (virtual DOM), `dioxus` (heavier runtime) |
| `wasm-bindgen`, `js-sys`, `web-sys`, `wasm-bindgen-futures` | Browser APIs: EventSource (SSE), fetch, DOM | `gloo` wrappers (extra layer) |
| `serde_json` | Decode snapshots | `serde-wasm-bindgen` (would parse in JS first) |

The only JavaScript is `ui/static/boot.js`, a three-line module loader that
browsers require to instantiate WebAssembly. The remaining JS
(`wm_ui.js`) is glue generated by `wasm-bindgen`.

## Development and test

| Crate | Why |
|---|---|
| `proptest` | Property tests: units, gate state machine, METAR parser, outcome mapping, fill model, risk engine, bucket probability bounds, kernel safety invariant |
| `wiremock` | Mock HTTP providers (429/Retry-After/5xx/timeouts/malformed/304) |
| `tower` (util) | In-process HTTP tests of the axum router |
| `sqlx` (dev, `wm-app`) | Assertions against PostgreSQL in runtime tests |

## Evaluated and deliberately not used

| Candidate | Decision |
|---|---|
| `rust_decimal` | **Not used.** Money and prices are integer micro-units (`Price` u32, `Usd`/`Shares` i64), which Polymarket's 6-decimal collateral makes exact. Rounding direction is explicit (fees up, proceeds down) and arithmetic is faster. Decimal strings (`"10.00"`) are parsed exactly at the configuration boundary. |
| `rayon` | **Not yet.** A backtest day is sequential by design (knowledge-time order). Parameter sweeps are embarrassingly parallel and will use `rayon` over independent runs when Phase 7–10 sweeps exist; adding it now would be unused code. |
| `governor` (GCRA rate limiter) | **Not used.** It limits rate only. Providers here also need `Retry-After`, escalating politeness after throttling, a circuit breaker, a daily budget, concurrency caps, per-class hard floors and an auditable state snapshot. `wm-net::GateCore` is a small pure state machine with property tests, so every rule is visible and testable. |
| `tower::limit` / `backoff` crates | Same reason: partial features. The gate composes all of them. |
| `moka` (cache) | Not needed: conditional GET plus one in-memory `ResponseCache` per fetcher; persistent caching is PostgreSQL. |
| Scraping crates (`scraper`, headless browsers) | Not used: HTML scraping is the last-resort tier and no scraper is required (see §7–8). |
